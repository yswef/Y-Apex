بعد موافقة المستخدم

دليل سريع

كيف تستخدمه بأمان؟

لا تجرّب قواعد الحجب على جهاز يومي. الواجهة لا تطبّق أي تغيير عند مجرد فتحها أو قراءة الاتصالات.

  1. 1

    ابدأ داخل جهاز وهمي

    أنشئ لقطة استعادة، واستخدم ملف اختبار تملكه. راجع خطة الاختبار.

  2. 2

    راجع العملية والمسار

    تعرض القائمة اسم البرنامج ومساره وبعض بيانات الهوية. بصمة الملف والتوقيع قرائن فقط؛ قاعدة Windows Firewall تُطابق المسار ولا تُثبّت هوية الناشر.

  3. 3

    اختر الإجراء ثم اقرأ المعاينة

    حجب يضع قواعد واردة وصادرة. السماح بالصادر لا يفتح منفذاً وارداً، ويترك إعدادات Windows Firewall الافتراضية قائمة.

  4. 4

    اختبر الاتصال أو تراجع

    بعد التطبيق اختبر البرنامج. أكد أن الاتصال يعمل للاحتفاظ بالتغيير، أو استخدم «تراجع». إن لم تؤكد خلال 30 ثانية، يحاول التطبيق استعادة الحالة السابقة.

  5. 5

    استخدم الطوارئ عند الحاجة

    أمر الطوارئ يعرض معاينة ويحذف قواعد Y-Apex ذات علامة الملكية فقط بعد تأكيد صريح. لا يحذف قواعد Windows أو التطبيقات الأخرى.

التصميم

مكوّنات التطبيق

01 / واجهة

WPF بصلاحيات المستخدم

عرض الاتصالات والقواعد والاستهلاك والسجل. الواجهة لا تملك صلاحية تغيير الجدار بنفسها.

02 / خدمة

خدمة Windows محلية

تستخدم Windows Firewall COM وواجهات IP Helper وETW. تعمل بصلاحية مرتفعة، لذا تبقى واجهتها محدودة ومقيدة.

03 / قناة

Named Pipe مقيدة

رسائل محددة الإصدار والحجم، تحقق صارم من الحقول، ACL للمستخدم المسجل والمسؤولين وSYSTEM، وحدود للطلبات.

04 / تحديث

لا مصدر تحديث شبكي

فاحص التحديث الحالي محلي فقط. لا توجد خدمة telemetry أو تنزيل قوائم أو updater تلقائي في الشيفرة الحالية.

اقرأ قبل الاستخدام

ما الذي لا يفعله Y-Apex؟

وجود عنصر في الواجهة أو مشروع في الحل لا يعني أن القدرة منفّذة أو متحققة.

  • لا يوجد موفر WFP فعّال. طبقة WFP تجريبية غير منفذة؛ التنفيذ الحالي لإدارة القواعد هو Windows Firewall.
  • لا يوجد strict mode. ليس هناك حظر افتراضي شامل أو قائمة سماح تشغيلية.
  • لا يوجد DNS مشفّر أو حجب نطاقات ومتعقبات. لا توجد قوائم تهديدات أو مكافحة برمجيات خبيثة.
  • لا يوجد تاريخ دائم لاتصالات الشبكة أو الاستهلاك. عدادات ETW موجودة في الذاكرة، وتبدأ من جديد مع الخدمة.
  • الاتجاه غير موثوق في مصدر الاتصالات. تعرض واجهة IP Helper الاتجاه «غير معروف»، وUDP يعرض نقاط الربط المحلية فقط.
  • التوقيع لا يربط القاعدة بالناشر. Windows Firewall يعتمد على مسار الملف؛ قد يتغير الملف بعد التحقق.
  • لم يكتمل اختبار VM التفاعلي. بناء CI واختبارات الوحدات لا يثبتان سلامة التثبيت أو فاعلية الجدار.

البيانات والثقة

الأمان والخصوصية

البرنامج يتعامل مع بيانات حساسة ومع قواعد جدار الحماية؛ إليك ما يحدث وما لا يحدث.

المعلومات محلية

أسماء العمليات ومساراتها وعناوين IP وحجوم النقل لا تُرسل إلى خادم بواسطة الشيفرة الحالية. سجل القواعد في ProgramData محمي بـACL وDPAPI بنطاق الجهاز؛ قد يستطيع المسؤول المحلي قراءته أو تغييره.

التصدير يكشف بيانات

ملفات JSON/CSV قد تحتوي أسماء العمليات والمسارات وعناوين IP والمنافذ والتوقيتات. اختر موقعاً آمناً ولا تشاركها إلا عند الحاجة.

المسؤول المحلي خارج الحماية

Y-Apex لا يحمي جهازاً من مسؤول Windows مخترق، ولا يحل محل مضاد الفيروسات أو Windows Defender Firewall أو VPN.

البناء والتثبيت

كيف أحصل على Y-Apex؟

لا يوجد تنزيل عام

لن تجد رابط تثبيت عام بعد. ملفات CI المؤقتة مخصصة للاختبار وليست إصدارات موقعة أو موصى بها للتثبيت.

بناء الشيفرة للمطورين

يتطلب الحل Windows x64 و.NET 10 SDK؛ استعادة حزم NuGet أثناء البناء تحتاج اتصالاً بالإنترنت. لا يحتاج التطبيق نفسه إلى اتصال شبكي تلقائي.

dotnet restore YApex.sln
dotnet build YApex.sln -c Release --no-restore
dotnet test YApex.sln -c Release --no-build

راجع دليل البناء المحلي وبوابة الإصدار. لا تختبر الحجب إلا في VM بلقطة استعادة.

الإجابات الواضحة

أسئلة شائعة

هل يحجب Y-Apex الاتصالات تلقائياً؟

لا. عرض الاتصالات لا يغير الجدار. تطبيق القاعدة يتطلب معاينة وتأكيداً صريحاً. التغيير غير المؤكد يدخل نافذة تراجع مدتها 30 ثانية.

هل خيار السماح يفتح الاتصالات الواردة؟

لا. الإصدار الحالي يضيف قاعدة سماح صادرة فقط. الحجب ينشئ قاعدتي حجب واردة وصادرة، وإعدادات Windows Firewall الأخرى تظل سارية.

هل Y-Apex منافس جاهز لـPortmaster أو GlassWire؟

ليس بعد. إنه مشروع تطوير غير منشور بلا اختبار تثبيت/حجب تفاعلي مكتمل في Windows VM، ويفتقر إلى DNS الآمن وحجب النطاقات والتاريخ الطويل.

هل يوجد WFP أو وضع صارم؟

لا. طبقة WFP التجريبية غير منفذة، وخيار strict mode غير متاح. إدارة القواعد الحالية تمر عبر Windows Firewall.

ما البيانات التي تُرسل إلى الإنترنت؟

لا توجد في الشيفرة الحالية قناة telemetry أو updater أو مصدر تحديثات شبكة. استعادة الحزم للمطورين أثناء البناء أمر منفصل. راجع إشعار الخصوصية.

هل سجل الاستهلاك يبقى بعد إعادة التشغيل؟

لا. عدادات ETW في ذاكرة الخدمة منذ بدء التشغيل، وتُصفّر عند توقفها. سجل قواعد Y-Apex منفصل عن سجل حركة الشبكة.

كيف أحذف قواعد البرنامج عند إزالته؟

الإزالة التفاعلية تسأل قبل حذف قواعد Y-Apex والبيانات المشتركة. اختيار «لا» أو الإزالة الصامتة يترك القواعد والبيانات. راجع تعليمات التنظيف في وثائق الإصدار قبل إزالة أي برنامج.

What the current source implements

Current scope

These describe repository code, not a claim that the product has passed end-user testing on Windows.

01

Connection snapshots

Reads local TCP and UDP tables and associates entries with processes where Windows permits. The UI refreshes periodically and prompts when it observes a new program's first connection; this is not durable connection history.

IP Helper
02

Reviewed rule changes

Preview each rule's direction and action before confirmation. Block adds inbound and outbound rules; Allow adds an outbound rule only.

30-second rollback
03

Local journal and usage

Y-Apex rule changes are journaled locally. ETW counters count bytes from service start and reset when the service restarts.

No persistent usage history
04

Export and control

Export the current connection view to JSON or CSV and recent rule-journal events. Files are not sent automatically.

User initiated

Quick guide

How to use it safely

Do not test firewall rules on your everyday machine. Merely opening the app or reading connections does not change the firewall.

  1. 1

    Start in a virtual machine

    Create a restore snapshot and use a test executable you own. See the test plan.

  2. 2

    Check the process and path

    The list shows the app name and path plus some identity information. Hash and signature are clues only: Windows Firewall matches the path, not a cryptographically pinned publisher.

  3. 3

    Choose an action and read the preview

    Block adds inbound and outbound block rules. Allow outbound does not open inbound access; existing Windows Firewall defaults remain in force.

  4. 4

    Test connectivity or undo

    After applying a change, test the app. Confirm that connectivity works to keep the change, or use Undo. If you do not confirm within 30 seconds, the app attempts to restore the previous state.

  5. 5

    Use emergency removal if needed

    The emergency flow previews and removes only rules with Y-Apex ownership metadata after explicit confirmation. It does not request deletion of Windows or other apps' rules.

Design

Application components

01 / UI

Unprivileged WPF client

Shows connections, rules, usage, and journal. The UI itself does not have permission to change the firewall.

02 / Service

Local Windows service

Uses Windows Firewall COM, IP Helper, and ETW. It runs with elevated privileges, so its command surface is deliberately limited.

03 / IPC

Restricted named pipe

Versioned, size-limited messages, strict field validation, an ACL for the enrolled user, Administrators and SYSTEM, and request limits.

04 / Updates

No network update source

The current update check is local only. The source contains no telemetry service, list downloader, or automatic updater.

Read before use

What Y-Apex does not do

A UI element or project in the solution does not mean the capability is implemented or validated.

  • No active WFP provider. The experimental WFP layer is unimplemented; current rule management uses Windows Firewall.
  • No strict mode. There is no operational default-deny mode or allow-list.
  • No encrypted DNS, domain filtering, or tracker lists. No threat-intelligence feed or malware scanner is included.
  • No persistent network or usage history. ETW counters are held in memory and reset with the service.
  • Connection direction is not reliable. The IP Helper source reports direction as unknown; UDP rows show local sockets only.
  • A signature does not bind the rule to a publisher. Windows Firewall uses the executable path; a file can change after verification.
  • Interactive VM validation is outstanding. CI builds and unit tests do not prove installer safety or firewall enforcement.

Data and trust

Security and privacy

The app handles sensitive metadata and firewall rules. Here is what it does and does not do.

Data stays local

The current source does not send process names, paths, IP addresses, or usage counters to a server. The ProgramData rule journal is ACL-restricted and protected with machine-scope DPAPI; a local administrator can still read or alter it.

Exports are sensitive

JSON/CSV files may contain process names, paths, IP addresses, ports, and timestamps. Choose a safe destination and share only when needed.

Local administrators are out of scope

Y-Apex cannot protect a machine from a compromised Windows administrator, and it is not a replacement for antivirus, Windows Defender Firewall, or a VPN.

Build and install

How do I get Y-Apex?

No public download

There is no public installer yet. Temporary CI artifacts are for testing and are not signed or recommended for installation.

Build from source for development

The solution requires Windows x64 and the .NET 10 SDK; restoring NuGet packages during the build requires internet access. The app itself makes no automatic network request.

dotnet restore YApex.sln
dotnet build YApex.sln -c Release --no-restore

Straight answers

Frequently asked questions

Does Y-Apex block connections automatically?

No. Viewing connections does not change the firewall. Applying a rule requires a preview and explicit confirmation. An unconfirmed change enters a 30-second rollback window.

Does Allow open inbound connections?

No. The current build adds an outbound allow rule only. Blocking creates inbound and outbound block rules; other Windows Firewall defaults remain in force.

Is Y-Apex ready to replace Portmaster or GlassWire?

No. It is an unreleased development project without a completed interactive Windows-VM install/block test, and it lacks secure DNS, domain filtering, and long-term history.

Is WFP or strict mode available?

No. The experimental WFP provider is unimplemented and strict mode is unavailable. Current rule management goes through Windows Firewall.

What data is sent over the internet?

The current source has no telemetry channel, updater, or network update source. Developer package restore is separate. Read the privacy notice.

Does usage history survive a restart?

No. ETW counters live in service memory from startup and reset when it stops. The Y-Apex rule journal is separate from network traffic history.

What happens to rules when I uninstall?

The interactive uninstaller asks before deleting Y-Apex rules and shared data. Choosing No or running a silent uninstall preserves them. See the release documentation before removing any software.
