# المعمارية

## الحدود والمشاريع

- `YApex.Core` يستهدف `net10.0` فقط. يحتوي النماذج والتحقق وقارئ بروتوكول Pipe ومنسق قواعد قابل للاختبار.
- `YApex.Service` يستهدف Windows. يتعامل مع Windows Firewall COM (`INetFwPolicy2`)، وواجهات IP Helper، وNamed Pipe، وSQLite.
- `YApex.UI` واجهة WPF تعمل بصلاحيات المستخدم (`asInvoker`) ولا تستدعي COM أو واجهات النظام ذات الصلاحية مباشرة.
- `YApex.Cli` يشخّص الخدمة وينفّذ إزالة الطوارئ عبر Pipe نفسه. لا يستدعي `netsh` أو `shell`.
- `YApex.Wfp` معزول؛ الخيار `experimentalWfpEnabled` مغلق افتراضياً. الموفر التجريبي غير منفذ بعد، وعند محاولة تفعيله يرمي خطأ توفر فيحوّل الغلاف إلى Windows Firewall. لا يوجد برنامج تشغيل أو فلترة WFP عاملة في هذا الإصدار.
- الاختبارات في `tests/YApex.Core.Tests` و`tests/YApex.Service.Tests`.

## حساب الخدمة

تُشغَّل الخدمة في المثبّت بحساب `LocalSystem` حالياً لأن تطبيق قواعد Windows Firewall عبر COM يتطلب صلاحيات إدارية على الجهاز، بينما تظل الواجهة `asInvoker`. هذا قرار محافظ يحتاج تأكيداً على Windows: واجهة القناة محدودة إلى أوامر معروفة، وتُحصر ACL في SYSTEM والمسؤولين وSID المستخدم الذي يسجله المثبّت، ويُرفض كل طلب غير صالح. لا تستخدم الخدمة صلاحية إدارية لتشغيل أوامر عامة. إذا أثبت اختبار Windows أن حساباً أقل صلاحية يستطيع إدارة القواعد بنفس الضمانات، يجب خفض صلاحية الخدمة قبل الإصدار.

## Named Pipe

- الاسم: `Y-Apex.Control.v1`.
- ACL تُنشأ عبر `PipeSecurity`؛ المسموح لهم SYSTEM والمسؤولون وSID المستخدم المحفوظ في `%ProgramData%\YSWEF\Y-Apex\pipe-user.sid`. أثناء التثبيت يسجل CLI SID مستخدم سطح المكتب في جلسة المثبّت، ثم يشغّل المثبّت الواجهة بصلاحيات المستخدم الأصلية.
- إذا لم يسجل المثبّت SID مستخدماً بعد، فالافتراضي SYSTEM والمسؤولون فقط؛ يفشل الوصول العادي بأمان ولا يُفتح للـ `Everyone`.
- رسائل JSON مؤطرة بطول 32-bit، إصدار البروتوكول 1، حد 64 KiB، عمق JSON محدود، رفض الحقول غير المعروفة والمكررة، مهلة 10 ثوانٍ وحد 120 اتصالاً/طلباً في الدقيقة. تتضمن الأوامر قراءة صفحات الاتصالات وحالة عمليات التراجع النشطة.
- يعيد الخادم هوية العميل بعد انتحال pipe مؤقتاً، ويتحقق من SID بالإضافة إلى ACL.

## قواعد الجدار

`RuleChangeCoordinator` يبني معاينة دون تعديل النظام. بعد موافقة صريحة يكتب حالة `Planned` في journal ثم يستبدل قواعد البرنامج. القواعد التي ينشئها التطبيق موسومة بعلامة ملكية ثابتة في الاسم والوصف، ولا يحذف أو يعدل قاعدة لا تطابق العلامة والبيانات المحسوبة. التراجع اليدوي والمؤقت يعيدان النسخة السابقة؛ المؤقت الافتراضي 30 ثانية. الطوارئ تزيل القواعد الموسومة فقط.

تُربط القاعدة بمسار الملف وبصمة SHA-256 وحالة التوقيع في الوصف/السجل، ويعيد service فحص الهوية بين المعاينة والتطبيق. لكن محرك Windows Firewall يطابق الملف بالمسار، لا يفرض بصمة الناشر؛ لذلك يمكن لمسؤول محلي استبدال الملف، ويجب إعادة التحقق قبل التغيير. لا يوجد وضع صارم في هذه النسخة.

## الاتصالات والتوقيع

تقرأ الخدمة جداول TCP وUDP حسب PID عبر IP Helper، ثم تربط PID بمسار البرنامج واسمه. تتحقق من Authenticode عبر `WinVerifyTrust` وتقرأ الناشر وبصمة الملف. جدول TCP يعرض الحالة؛ واجهات IP Helper المستخدمة لا تعطي اتجاهاً موثوقاً لكل صف، لذلك يظهر الاتجاه «غير معروف». جدول UDP يعرض منافذ الربط المحلية ولا يملك وجهة بعيدة لكل مقبس UDP.

## التخزين والخصوصية

- إعدادات الواجهة: `%APPDATA%\YSWEF\Y-Apex\ui-settings.json`.
- بيانات الخدمة المشتركة وSQLite: `%ProgramData%\YSWEF\Y-Apex`، مع ACL مقصورة على SYSTEM والمسؤولين. هذا استثناء مقصود من `%APPDATA%`: حساب الخدمة لا يرى مجلد AppData الخاص بالمستخدم.
- SQLite يحفظ journal التغييرات بحد أقصى لحجم الإدخال وقيود حجم/ملف WAL. تشفير DPAPI متاح اختيارياً في طبقة الكتابة، لكنه غير مفعّل من واجهة الإعدادات حالياً.
- لا يجمع التطبيق بيانات إلى خادم ولا يجري اتصال تحديث تلقائياً. `IUpdateChecker` الحالي يعيد رسالة محلية ولا يستخدم الشبكة.
- مصدر ETW مربوط بالخدمة، وتعرض الواجهة ملخصات الاستخدام منذ بدء الخدمة. العدادات في الذاكرة ولا تُحفظ بين مرات التشغيل. سجل التغييرات يعرض الإدخالات الحديثة ويُصدّرها؛ تصدير الاتصالات مقتصر على الصفحة الحالية والبحث المطبق.
- مطالبة أول اتصال تحفظ بصمات SHA-256 لمسارات البرامج في إعدادات المستخدم لتقليل تكرار السؤال؛ لا تُحفظ المسارات نفسها في هذا الإعداد.

## التحديث

كل تعامل مع Windows وراء واجهات Core: `IFirewallBackend` و`IConnectionSource` و`IUsageSource` و`IClock` و`IProgramIdentitySource` و`IChangeJournal`. توجد بدائل وهمية في الاختبارات. التنفيذ الفعلي لـ `IUsageSource` يستخدم ETW ويعلن حالة التوفر والاقتطاع؛ تُجمع العدادات من بدء الخدمة فقط، ولا تعرض الواجهة بيانات تاريخية غير موجودة.
