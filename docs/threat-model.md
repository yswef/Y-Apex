# نموذج التهديدات (STRIDE)

## النطاق والحدود

يشمل هذا النموذج واجهة WPF بصلاحيات المستخدم، وخدمة Windows، وقناة Named Pipe بينهما، ومخزن بيانات الخدمة في `%ProgramData%`، ومخزن إعدادات الواجهة في `%APPDATA%`، وواجهة Windows Firewall. يعمل التطبيق محلياً دون اتصال خارجي تلقائي. طبقة WFP والمحدّث غير مفعّلين افتراضياً.

واجهة المستخدم غير موثوقة حتى لو كانت نسخة Y-Apex الرسمية: يمكن تعديل ملفاتها أو إرسال رسائل مصاغة يدوياً إلى الخدمة. الخدمة هي نقطة تنفيذ التغيير ذات الصلاحيات، ولذلك تتحقق من كل طلب بنفسها ولا تعتمد على تحقق الواجهة. كما أن اسم العملية أو اسم الملف ليسا هوية موثوقة.

## سجل STRIDE

| المكوّن / الحد | التهديد | النوع | المعالجة المطلوبة |
|---|---|---|---|
| Named Pipe | برنامج محلي ينتحل الواجهة أو يفتح القناة بلا إذن | انتحال الهوية (Spoofing) | استخدم اسماً ثابتاً للقناة، وACL تسمح فقط بـ SID المستخدم الذي سجّله المثبّت والمسؤولين. ارفض الاتصالات المجهولة، ولا تعتبر اسم العملية أو PID إثباتاً للهوية. تحقّق من صلاحية كل عملية في الخدمة. |
| Named Pipe | عميل يرسل إصداراً أو JSON أو حقولاً غير متوقعة | العبث (Tampering) | إطار رسالة محدد الإصدار، طول أقصى صغير، JSON صارم مع رفض الحقول المكررة وغير المعروفة، تحقق من كل enum والمسار، والرفض الآمن لأي طلب غير صالح. لا تُمرر مدخلات إلى shell أو `netsh`. |
| Named Pipe | إعادة إرسال طلب قديم أو تكرار أمر التغيير | العبث / إنكار | معرّف طلب فريد، معالجة idempotent، ورفض انتقالات الحالة غير المسموحة. يكتب سجل العملية والنتيجة قبل إقرار نجاحها. |
| Named Pipe | اتصالات متزامنة أو رسائل بطيئة تستنزف موارد الخدمة | حجب الخدمة (Denial of Service) | حد لحجم الرسالة، مهلة قراءة، حد للاتصالات والطلبات في الثانية، إلغاء للعمليات، ودفعات محدودة. لا تنفّذ عملاً غير محدود على خيط الخدمة. |
| خدمة Windows | عميل عادي يستغل الخدمة لرفع صلاحياته أو لتنفيذ إجراء عام | رفع الصلاحيات (Elevation of Privilege) | لا توجد واجهة تنفيذ أوامر عامة. عرّف أوامر محدودة (استعلام، معاينة، تطبيق قاعدة، تراجع، طوارئ) مع تحقق خدمة مستقل، وتقييد المسارات والاتجاهات والسياسات. استخدم حساب خدمة وSID مقيدين قدر الإمكان؛ لا تمنح الواجهة صلاحيات إدارية. تغييرات COM تتطلب صلاحيات إدارية، لذا يلزم اختبار حساب الخدمة على Windows وتوثيق أي صلاحية إضافية قبل الشحن. |
| خدمة Windows / Windows Firewall | حذف قواعد أو تعديل قواعد مستخدم أو منتج آخر | العبث | أضف علامة ملكية ثابتة لـ Y-Apex في الاسم والوصف، واحصر كل القراءة والحذف والتعديل على قواعد تحمل العلامة المطابقة. لا تعتمد على بادئة الاسم وحدها إن أمكن تضمين GUID للقاعدة. اعرض اتجاه وإجراء كل قاعدة في المعاينة، واطلب تأكيداً صريحاً، واكتب journal قابل للاستعادة قبل التغيير، ووفّر تراجعاً وطوارئ. الحجب يضع قاعدتي وارد وصادر؛ السماح العادي لا ينشئ سماحاً وارداً. |
| مسار البرنامج / قاعدة الجدار | تزوير اسم العملية، تبديل الملف بعد التحقق، أو استخدام رابط رمزي | انتحال الهوية / رفع الصلاحيات | طبّع المسار، ارفض المسارات النسبية وUNC والـ traversal، وافحص reparse points/الروابط الرمزية باستخدام مقابض ملفات نهائية قبل التغيير. خزّن بصمة الملف وبيانات التوقيع والناشر وعاود التحقق عند التطبيق. قاعدة Windows Firewall تربط المسار لا التوقيع تشفيرياً، لذلك لا تُقدّم التوقيع كضمان منع استبدال الملف؛ أعد الفحص بعد تحديث الملف وأظهر اختلاف الهوية. |
| إعدادات `%APPDATA%` | استبدال ملف إعداد أو إدخال رابط/مسار ضار | العبث / رفع الصلاحيات | لا تقرأ الخدمة إعدادات المستخدم. استخدم JSON محدوداً ومتحققاً، كتابة ذرية، مسارات تحت مجلد التطبيق المعروف، ورفض الروابط الرمزية غير المتوقعة. لا تنفّذ الروابط من الإعداد إلا بعد تأكيد المستخدم. |
| بيانات الخدمة `%ProgramData%` | مستخدم عادي يغيّر سجل القواعد أو ملف التراجع | العبث / إنكار | أنشئ المجلد وملفاته بصلاحيات ACL مقيدة للخدمة والمسؤولين، وتحقق من ACL والروابط الرمزية عند البدء. خزّن journal محدود الحجم مع schema/version، ورفض البيانات التالفة بدلاً من تطبيقها. SQLite/DPAPI لا يجعل السجل غير قابل للتلاعب من مسؤول محلي. |
| السجل والاستهلاك | كشف مسارات البرامج أو عناوين IP أو أحجام الاستخدام | كشف المعلومات (Information Disclosure) | اجمع الحد الأدنى، لا ترسل البيانات خارج الجهاز، واحصر صلاحية ملفات `%ProgramData%` والمخرجات المصدّرة. نبّه قبل التصدير، ولا تضع بيانات حساسة في رسائل الأخطاء. طبّق تدويراً وحدوداً للحجم. |
| سجل التراجع | تعطل التطبيق بين حفظ التغيير وتأكيده، أو فساد السجل | العبث / إنكار | اكتب عملية journal بحالة واضحة (مخطط لها، مطبقة، معكوسة)، واستخدم كتابة ذرية/معاملة مناسبة، وافحص الحالة عند بدء الخدمة. لا تعلن نجاح التراجع قبل نجاح إزالة قواعد Y-Apex، واعرض خطأً قابلاً للفهم عند فشل الاستعادة. |
| وضع الحجب الصارم (غير منفذ) | تنفيذ مستقبلي خاطئ يقطع DNS/DHCP أو اتصال المستخدم | حجب الخدمة | الوضع غير موجود حالياً. إذا أُضيف مستقبلاً، فيجب أن يكون مغلقاً افتراضياً، مع معاينة وقائمة سماح موثقة وتراجع تلقائي واستعادة مجرّبة؛ لا يُختبر إلا داخل VM معزول. |
| زر الطوارئ | الأمر يزيل قواعد ليست ملك Y-Apex أو لا يستطيع الوصول للخدمة | رفع الصلاحيات / حجب الخدمة | الأمر يطلب من الخدمة إزالة القواعد ذات علامة الملكية الدقيقة فقط. اعرض نتيجة كل قاعدة، ولا تستخدم `netsh` ولا حذفاً شاملاً. وفر CLI محدوداً يستدعي البروتوكول نفسه. |
| واجهة التحديث | تنزيل حزمة مزيفة أو اتصال خفي | العبث / كشف المعلومات | لا يوجد اتصال تلقائي. واجهة `IUpdateChecker` لا تفعل شبكة افتراضياً؛ التنفيذ الشبكي لا يضاف إلا بعد تزويد عنوان موثوق ومراجعة التوقيع. عند تنفيذه لاحقاً: تحقق من توقيع الحزمة وسلسلة الشهادة، ولا تنفّذ تحديثاً بلا موافقة المستخدم. |
| طبقة WFP | عطل أو خطأ في طبقة منخفضة المستوى يمنع الشبكة | حجب الخدمة / رفع الصلاحيات | معزولة في `YApex.Wfp`، مغلقة افتراضياً، لا تحتوي مشغلاً أو برنامج تشغيل حالياً، وتفشل إلى Windows Firewall. لا تحمل برنامج تشغيل ولا تستخدمها قبل مراجعة أمان مستقلة واختبارات استعادة في VM. |
| الاعتمادات والبناء | حزمة أو بناء CI ملوث يصل إلى المستخدم | العبث / رفع الصلاحيات | تثبيت نسخ الحزم، مراجعة الاعتمادات، تحليل Roslyn، CodeQL، فحص أسرار وحزم وSBOM في CI. لا يُنشأ إصدار تلقائي؛ التوقيع يتم بمدخلات خارج المستودع. |

## افتراضات ومخاطر متبقية

- المسؤول المحلي أو البرمجية التي تعمل بصلاحياته قادر على تعديل الجدار والملفات؛ Y-Apex لا يحمي من مسؤول مخترق.
- إثبات هوية ملف عبر توقيعه أو بصمته يحتاج إلى إعادة تحقق، وقد يتغير الملف بعد إنشاء قاعدة الجدار.
- خدمات Windows Firewall وETW وسلوك ACL يجب اختبارها على إصدارات Windows مدعومة؛ لا يمكن إثبات ذلك على أنظمة غير Windows.
- وظيفة نقطة الاستعادة تعني نسخة قابلة للاسترجاع من حالة قواعد Y-Apex في هذه النسخة، لا نقطة استعادة كاملة لنظام Windows.
- أي فشل في حفظ journal أو التحقق من الملكية يمنع تغيير النظام؛ لا تُتجاوز هذه الشروط لتسهيل التشغيل.

## اختبارات مرتبطة

اختبر القارئ برسائل عشوائية ومبتورة وكبيرة وإصدارات مجهولة، واختبر المسارات النسبية وUNC و`..` والروابط الرمزية والحروف غير الصحيحة، واختبر رفض قاعدة لا تحمل علامة Y-Apex، وفشل التراجع وانقطاع الخدمة. اختبار COM الذي يغيّر قواعد الجدار محصور في runner/VM معزول. لا توجد بعد نتيجة موثقة لبوابة التثبيت والجدار التفاعلية في Windows VM؛ راجع `docs/release.md` قبل أي إصدار.
