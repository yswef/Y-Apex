# الإصدار والتوزيع

1. شغّل CI على Windows وراجع بناء Release والاختبارات وفحص الحزم وCodeQL وgitleaks وSBOM. ينشئ CI حزمة اختبار `Y-Apex-Windows-x64` تتضمن Portable والمثبّت وSHA256SUMS؛ هذا artifact للاختبار وليس إصداراً موقّعاً.
2. للمراجعة المحلية، أنشئ `out/portable` و`SHA256SUMS.txt` بالسكربتات تحت `tools/`.
3. أنشئ المثبّت من `installer/Y-Apex.iss` باستخدام Inno Setup بعد نشر المشاريع المطلوبة.
4. فحص VirusTotal غير مفعّل في CI لأنّه يرفع ملفات التنفيذ إلى طرف ثالث. يمكن تشغيل `tools/virustotal-scan.ps1` يدوياً فقط بعد موافقة صريحة من مالك المشروع.
5. يُوقّع exe والمثبّت عبر شهادة أو خدمة توقيع خارج المستودع. لا تحفظ شهادة خاصة أو كلمة مرور في Git.
6. اختبر التثبيت والإزالة والتراجع والطوارئ في VM، وتحقق من إزالة قواعد Y-Apex فقط. الإزالة التفاعلية تسأل قبل حذف القواعد وبيانات الخدمة؛ الإزالة الصامتة تحفظها افتراضياً.
7. لا يوجد نشر أو Release تلقائي في CI. أي إصدار يحتاج إذناً صريحاً من المالك.

لا يُعد وجود سكربت توزيع دليلاً على نجاحه؛ يجب تنفيذ الاختبارات على Windows قبل اعتبار الحزمة جاهزة.
