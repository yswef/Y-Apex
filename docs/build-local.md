# البناء والتشغيل محلياً على Windows

## ما الذي تحتاج إلى تثبيته؟

1. Windows 11 x64 (أو إصدار Windows مدعوم) وجهاز وهمي للاختبار. لا تختبر الحجب على جهازك الأساسي.
2. .NET 10 SDK. هو إصدار LTS الحالي وقت إعداد هذه الوثيقة.
3. Visual Studio 2026 أو Visual Studio Community مع حمل **.NET desktop development** لبناء WPF والتصحيح. يمكن استخدام PowerShell و`dotnet` من دون Visual Studio.
4. Inno Setup 6 إذا أردت إنشاء المثبّت.
5. Python 3 اختياري لتصدير SVG إلى PNG وICO.

## بناء الحل خطوة بخطوة

افتح PowerShell في جذر المستودع ثم نفّذ الأوامر بالترتيب:

```powershell
dotnet --list-sdks
```

المتوقع: يظهر SDK يبدأ بـ `10.0.`. إذا لم يظهر، ثبّت .NET 10 SDK وأعد فتح PowerShell.

```powershell
dotnet restore YApex.sln
```

المتوقع: تُحل مراجع NuGet ويكتمل الأمر دون خطأ. أول مرة تتطلب اتصالاً بمصدر NuGet أثناء التطوير؛ لا يحتاج البرنامج نفسه إلى اتصال خارجي.

```powershell
dotnet build YApex.sln -c Release --no-restore
```

المتوقع: `Build succeeded`. هذا الحل يحتوي WPF وخدمة Windows، لذلك بناؤه الكامل يتطلب Windows.

```powershell
dotnet test YApex.sln -c Release --no-build
```

المتوقع: نجاح اختبارات Core واختبارات Windows. اختبارات الخدمة تقرأ معلومات النظام ولا تطبق قواعد جدار.

لبناء Core واختباراته على Linux/macOS (مع تثبيت .NET 10 SDK):

```powershell
dotnet test tests/YApex.Core.Tests/YApex.Core.Tests.csproj -c Release
```

## هل تُنزَّل المكتبات مرة واحدة؟

عادةً نعم. ينزّل `dotnet restore` نسخ NuGet المطلوبة لأول مرة إلى مخزن المستخدم المحلي (`%USERPROFILE%\.nuget\packages`). بعد ذلك يعيد البناء استخدام النسخ المخزنة، ويتحقق `restore` من النقص أو تغير ملفات المشروع. إذا حذفت المخزن أو غيّرت نسخة حزمة فسيُنزَّل ما يلزم من جديد. هذا خاص ببيئة التطوير؛ التطبيق لا ينزّل مكتبات أو تحديثات أثناء التشغيل.

## تشغيل الخدمة والواجهة في جهاز وهمي

1. افتح PowerShell **كمسؤول** داخل VM، وانتقل إلى جذر المستودع.
2. سجل SID حساب سطح المكتب الذي سيشغل الواجهة، مرة واحدة، **قبل بدء الخدمة**. هذا الأمر يحتاج PowerShell مسؤولاً ويقرأ SID جلسة سطح المكتب الحالية حتى عند استخدام بيانات اعتماد مسؤول مختلفة. إذا كانت الخدمة تعمل مسبقاً، أوقفها وأعد تشغيلها بعد التسجيل ليُعاد إنشاء ACL القناة:

```powershell
dotnet run --project src/YApex.Cli/YApex.Cli.csproj -- register-pipe-user --interactive
```

المتوقع: رسالة تؤكد تسجيل SID. يكتب الأمر في `%ProgramData%\YSWEF\Y-Apex\pipe-user.sid` بصلاحيات مقيدة. إذا لم تكن جلسة سطح مكتب تفاعلية مفتوحة، سجّل دخول المستخدم المستهدف أولاً. لا تتابع الحجب قبل أن تتمكن الواجهة من الاتصال بالخدمة.

3. في نافذة PowerShell أخرى **كمسؤول** شغّل الخدمة:

```powershell
dotnet run --project src/YApex.Service/YApex.Service.csproj -- --service
```

المتوقع: تبقى الخدمة عاملة في النافذة دون خطأ. وسيط `--service` يشغّل المضيف في وضع الاختبار التفاعلي؛ الإغلاق يوقفه. لا تحذف هذا الوسيط.

4. افتح PowerShell بصلاحيات عادية في جذر المستودع وشغّل الواجهة:

```powershell
dotnet run --project src/YApex.UI/YApex.UI.csproj
```

المتوقع: تظهر النافذة، وحالة الخدمة «تعمل». إذا ظهرت «غير متاحة»، اترك نافذة الخدمة مفتوحة، وتحقق من SID المسجل وACL للقناة.

5. قبل أي تجربة حجب، أنشئ لقطة VM. اختر برنامج اختبار تملكه، اعرض المعاينة، تحقق من المسار والتوقيع، ثم أكد. استخدم «تراجع» أو اترك مؤقت الثلاثين ثانية ينتهي. لا تحجب Windows أو Y-Apex أو برنامج الحماية.

6. أمر الطوارئ المكافئ من PowerShell كمستخدم إداري:

```powershell
dotnet run --project src/YApex.Cli/YApex.Cli.csproj -- emergency-remove
```

المتوقع: يطبع عدد قواعد Y-Apex التي أزيلت. الأمر لا يزيل قواعد أخرى. استخدم `status` لفحص عدد القواعد المسجلة.

## أخطاء شائعة

- **`dotnet` غير معروف:** ثبّت .NET 10 SDK وأعد فتح PowerShell.
- **`NETSDK1005` أو ملف assets غير موجود:** شغّل `dotnet restore YApex.sln` بعد تغيير ملفات المشروع.
- **بناء WPF على Linux:** استخدم اختبار مشروع Core فقط؛ الواجهة والخدمة غير قابلتين للتشغيل هناك.
- **`Access denied` عند تعديل Firewall:** شغّل الخدمة من نافذة مسؤول داخل VM، وليس الواجهة.
- **Pipe access denied:** سجّل SID قبل تشغيل الخدمة. إذا سجّلته بعد تشغيلها، أوقف الخدمة وأعد تشغيلها كي تُنشأ قناة جديدة بالـ ACL المحدّثة، ثم أعد فتح الواجهة.
- **تعذر التحقق من توقيع ملف:** استخدم ملفاً محلياً يمكن قراءته؛ التحقق يعمل دون تنزيل سلسلة شهادات، لذلك قد يظهر ملف صحيح التوقيع كغير متحقق إن لم تكن بيانات الثقة متاحة محلياً.
- **توقف الإنترنت في الاختبار:** استخدم التراجع أو انتظر 30 ثانية، ثم نفّذ أمر الطوارئ داخل VM وأعد اللقطة.

تتضمن الشيفرة الحالية ETW والاستهلاك في الذاكرة، مطالبة أول اتصال، وسكربت المثبّت؛ لكنها لم تُبنَ أو تُختبر على Windows هنا. موفر WFP الحقيقي والوضع الصارم ومصدر التحديث الشبكي غير منفّذة. استخدم CI وجهازاً وهمياً للتحقق قبل الاعتماد على أي تغيير في جدار الحماية.
